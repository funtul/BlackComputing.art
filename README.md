# Black Computing — сайт Аркадия Кукина

Эта папка и есть сайт целиком. Её содержимое лежит в корне репозитория GitHub и публикуется через GitHub Pages.

## Как поменять что-то на сайте

1. Откройте `editor.html` в **Google Chrome**: правой кнопкой по файлу → «Открыть с помощью» → Google Chrome (подойдёт и Microsoft Edge). Opera, Firefox и Safari не дают сайтам работать с папками — в них редактор не запустится.
2. Нажмите «Открыть папку сайта» и выберите **эту папку** (где лежат `content.json` и `index.html`). Chrome спросит разрешение на изменение файлов — разрешите. В следующий раз будет кнопка «Продолжить».
3. Слева откроется вся главная страница плитками, раздел за разделом. Правьте:
   - **Щёлкните по плитке** — справа откроется всё, что в ней: у проекта тексты (русский слева, английский справа), картинки (перетащите файлы в окно; первая картинка — плитка), видео YouTube, ссылки; у блоков — био, образование, фото, выставки, список игр, контакты. Щелчок по заголовку раздела — переименовать раздел.
   - **Тащите плитки мышью** — внутри раздела и в другой раздел. Размер меняйте за края и углы (картинки сохраняют пропорции). Красная рамка — плитки пересекаются, так сохранить нельзя; жёлтая — просто совет.
   - Внизу — **«Не на главной странице»**: туда уходят плитки, убранные кнопкой «Убрать с главной». Перетащите их обратно в сетку.
   - Сверху: **«+ проект»**, **«Artist Statement»**, **«Сайт»** (домен, описание, картинка превью). **«Превью»** показывает сайт с правками ещё до сохранения. «↶ Шаг назад» (или Ctrl+Z) отменяет последнее действие.
4. Нажмите **«Сохранить»** (Ctrl+S). Если сверху красный список — сначала исправьте то, что в нём написано (по ссылкам можно перейти).
5. Откройте **GitHub Desktop** → внизу слева напишите пару слов о правках → **Commit to main** → **Push origin**. Через 1–2 минуты сайт обновится.

Картинки можно класть любые (JPG, PNG, большие) — редактор сам уменьшит их и сделает миниатюры.
Если удаляли проекты или картинки, раз в какое-то время нажмите «Сайт и публикация» → «Удалить неиспользуемые файлы».

## Первая публикация (один раз)

1. Зарегистрируйтесь на github.com и установите GitHub Desktop.
2. В GitHub Desktop: File → New repository. Имя — **`<ваш-логин>.github.io`** (так сайт будет жить в корне адреса, и всё будет работать). Создайте его, затем скопируйте **содержимое** этой папки (не саму папку) в папку репозитория.
3. Commit to main → **Publish repository**, галочку «Keep this code private» **снять** (бесплатный GitHub Pages — только для публичных репозиториев).
4. На github.com откройте репозиторий → Settings → Pages → Source: **Deploy from a branch**, ветка `main`, папка `/ (root)` → Save. Через пару минут сайт откроется по адресу `https://<ваш-логин>.github.io/`.

Если репозиторий назван по-другому, адрес будет `https://<логин>.github.io/<имя>/` — сайт откроется, но страница «404» и некоторые ссылки будут вести мимо. Лучше сразу имя `<логин>.github.io` или свой домен.

## Свой домен

1. Купите домен у любого регистратора (например, имя.ru).
2. В редакторе: «Сайт и публикация» → Домен: `https://имя.ru` → Сохранить → Commit → Push. (В папке появятся файлы `CNAME` и `sitemap.xml`.)
3. В панели регистратора, в DNS-записях домена:
   - четыре записи **A** для самого домена (`@`): `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`;
   - запись **CNAME** для `www` → `<ваш-логин>.github.io`.
4. На github.com: Settings → Pages → Custom domain: `имя.ru` → Save. Когда проверка пройдёт (от нескольких минут до суток), включите **Enforce HTTPS**.

Ссылка на отдельный проект для соцсетей и мессенджеров: `https://имя.ru/p/<id проекта>/` — с картинкой и описанием в превью.

Если GitHub Pages плохо открывается у вас или у зрителей, ту же папку можно выложить на Cloudflare Pages, Netlify или любой хостинг статических сайтов — ничего переделывать не нужно.
